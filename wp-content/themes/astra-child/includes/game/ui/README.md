# 窗口层（UI 换代的方向）

> 委员长的方向：把"一长串卡片按钮"逐步换成**可拖动、可关闭的窗口**（在一个图层上），
> 由**指令**或**按钮**打开；**交易**这类还能**从对话里打开**。

## 怎么加一个新窗口（3 步，不改引擎）

```php
// includes/game/ui/windows.php（或你自己的内容文件）
crrg_ui_win_register('mylist', function (&$s, &$ctx, &$pc, $uid, $arg) {
    return [
        'note'  => '一行说明',
        'text'  => ['可以放整段文字', '每行一句'],
        'items' => [
            ['label' => '按钮名', 'k' => 'do_something', 'id' => '参数'],
            ['label' => '禁用示例', 'k' => 'noop', 'id' => '', 'off' => true],
        ],
    ];
}, ['title' => '标题', 'w' => 360, 'order' => 40]);
```

- **服务端只管"窗口里有什么"**；长什么样（拖动、关闭、叠放）由前端窗口管理器负责 ✓
- **窗口里的按钮就是原来那种按钮**（`k` / `id` → 同一个 `crrg_drill_do_act`）→ 老机制不用改 ✓

**打开它的三种方式**
1. 指令：在 `crrg_drill_do_act` 的语义映射里加一条（或直接 `crrg_ui_request_open($s, 'mylist')`）
2. 按钮：`['label'=>'打开清单','k'=>'win','id'=>'mylist']`（`k='win'` 是通用入口 ✓，支持 `id` 带参数如 `shop:tw_coop`）
3. 对话：在对话树节点/选项里写 `'open' => 'mylist'`（或 `'open' => 'trade:常守业'`）

## 前端（在 `page-drill.php` 里）

- 窗口管理器：`winOpen(payload)` —— 同一 id 重复打开＝刷新内容并置顶；标题栏可拖动；右上角 `×` 关闭；新窗口自动错位摆开 ✓
- 收到服务器返回时：`if (j.data.win) winOpen(j.data.win);` ✓
- 样式类：`.drl-wins`（图层）/`.drl-win`（窗口）/`.w-hd`（标题栏，拖动区）/`.w-bd`（内容）/`.w-bt`（按钮）

## 迁移建议（逐步，不搞大爆炸）

1. 先把**看状态类**（背包／身体／合约）从"卡片列表"改成"窗口" ✓（已完成）
2. 再把**交易类**（商店／与 NPC 换货）改成窗口 ✓（商店可选参数 + 对话打开 ✓ 已完成）
3. 之后每改一个系统：把它的面板区块从 `crrg_drill_panels` 里摘出来 → 变成窗口 ✓
4. 全部搬完后，再删原来的面板区块（**先铺开再删** ✓，避免半途玩家没得点）

## 六、写文案的约定（2026-10-01 补）

1. **玩家可见的字符串里，不要出现我的"工作标记"** ✗（`✓`／`✗`／`※`）——
   它们只该待在**注释**里 ✓。玩家看到的是"（同处的人看得见。）"，不是"（同处的人看得见 ✓）"。
2. **例外**：表示"已完成"的界面记号（步骤行的 `　✓ `）属于**有意设计** ✓，保留。
3. **文本自带说话人** ✓：动态日志的文本里就写上名字（如「验证器坐了下来。」），
   渲染端**不再**拼 `who` ✗（否则重复）。
4. 内部键（`ask`／`bt_start` 之类）绝不出现在玩家文本里 ✓（自检里有这条规则 ✓）。
