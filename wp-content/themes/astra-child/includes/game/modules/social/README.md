# 玩家互动模块（social）v1 · 2026-10-01

> 委员长要求：**加入玩家之间的互动模块，模块化** ✓
> 本文件说明：**该有什么**（设计依据 ✓）、**怎么接**（模块化 ✓）、**边界**（刻意不做什么 ✗）

## 一、先看现状（依据，不拍脑袋 ✓）

| 已有 | 位置 |
|---|---|
| 同地点在场列表 | `crrg_drill_presence()`（视图 `players` ✓） |
| 同处可见的发言／动作 | 日志 feed（`crrg_drill_feed_add()` ✓） |
| 组队与分红 | `crrg_drill_team_*`（指挥大厅 ✓） |
| 站内消息系统 | 网站 `includes/messages.php` ✓ |

**缺的** ✗：在场的人**点不动**（只显示名字 ✓）、没有**人对人的动作** ✗ → 这就是本模块要补的 ✓

## 二、本模块提供什么（v1）

| 动作 | k | 前提 | 落点 |
|---|---|---|---|
| **打个招呼** | `soc_wave` | 必须**同房间** | 房间日志（同处可见 ✓） |
| **递个东西**（赠予） | `soc_gift` | 必须同房间 | 对方**礼物盒**（可领 ✓） |
| **邀请组队** | `soc_invite` | 任意 | 对方**邀请栏**（接受即入队 ✓；邀请人无队则**自动建队** ✓） |
| **留一句话** | `soc_note` | 任意 | 对方**互动信箱**（留痕 ✓，120 字上限 ✓） |
| **收礼物／接受邀请／清信箱** | `soc_take` / `soc_accept` / `soc_clear` | —— | 自己的 `pc['social']` ✓ |

**窗口**：
- `player:<uid>` —— **对某个人**能做的事（打招呼／递东西／邀请／留话 ✓）
- `social` —— **我的互动**（留言／礼物／邀请 ✓）

**入口**：左栏「此刻同在此处（点一下可互动）」→ 点人名即开 ✓（`page-drill.php` 里 `players` 已改为结构化 ✓ 兼容旧字符串 ✓）

## 三、模块化怎么接（核心不认识本模块 ✓）

1. **动作**：核心 `crrg_drill_do_act()` 的兜底处调一次 `crrg_soc_do($k,$id,…)` ✓
   · 返回 **null** ＝"不是我的" → 继续原有兜底 ✓（所以加/删本模块**不影响核心** ✓）
2. **窗口**：本模块自己 `crrg_ui_win_register('player'/'social', …)` ✓（窗口层是注册制的 ✓）
3. **存储**：写在各角色**自己的** `pc['social']`（`inbox`/`gifts`/`invites` ✓，各留最近 30 条防膨胀 ✓）——不动全局表 ✓
4. **接线**：`functions.php` 两行 require ✓

## 四、边界（刻意不做 ✗）

- **不偷、不抢**：互动一律**自愿**（礼物要对方领 ✓、入队要对方接受 ✓）
- **不刷屏**：留言限 120 字、信箱留最近 30 条 ✓
- **不留后门**：`player` 窗口只显示公开信息（职务／卡级／是否同处 ✓），**不看对方背包** ✓
- **留痕**：所有留言／礼物都记来源与时间 ✓（可查 ✓）

## 五、下一步可选（按需要加 ✓）

1. **当面交易**（双方各自确认 ✓ 两步制）——比"赠予"更正式
2. **帮忙／协力**：把"某件事需要两个人"做成合作步骤（如一起抬料 ✓）
3. **同处可见的动作扩展**：拍肩、递烟、扶一把（都走 `soc_*` + feed ✓）
4. **演习外的通讯**：把"留话"接到网站的站内消息（跨场次也能收到 ✓）
